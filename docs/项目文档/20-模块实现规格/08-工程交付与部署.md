## 2. prod compose 结构

```yaml
services:
  caddy:
    image: caddy:2
    ports: ["80:80", "443:443", "443:443/udp"]   # 443/udp=HTTP/3
    volumes: [./deploy/Caddyfile:/etc/caddy/Caddyfile, caddy_data:/data, caddy_config:/config]
  app-blue:
    profiles: [blue]
    build: {context: ., dockerfile: apps/web/Dockerfile}
    # api 同理或同镜像多进程 简化：api 与 web 各自蓝绿（演示脚本里以 web 为切换主体）
  app-green:
    profiles: [green]
    build: {...}
  postgres: {image: pgvector/pgvector:pg17, volumes: [pgdata_prod:/var/lib/postgresql/data]}
  redis: {image: redis:7-alpine}
```

**共库原则**：蓝绿两组共用同一 postgres/redis——Fowler 蓝绿的前提是 schema 变更与发版解耦（expand-contract 纪律见 10-骨架/02 §7）。

## 3. 蓝绿脚本规格（deploy-blue-green.sh）

```
1 确定当前活跃色（caddy 上游名） 目标色=另一色
2 docker compose --profile <目标色> up -d --build --wait（healthz 通过）
3 sed 替换 deploy/Caddyfile 的 reverse_proxy upstream 到目标色容器
4 docker compose exec caddy caddy reload --config /etc/caddy/Caddyfile   # 平滑切流零停机
5 旧色保活 30s 观察期后可选 stop（默认保留 即天然回滚安全网）
回滚：脚本带 --rollback 反向执行 3-4
```

本地演示 `demo-bluegreen.sh`：起 compose、后台循环 curl（每 200ms 记录状态码）、切绿、断言循环期间 0 个非 200/连接错误、输出证据摘要。

## 4. CI 规格（ci.yml）

```
on: pull_request / push main
jobs:
  quality: pnpm install → lint → typecheck → test（vitest run）
  build: pnpm build + docker build 两镜像
  push(仅 main): 推 ghcr.io/<user>/agent-rag-{api,web}
deploy.yml: workflow_dispatch → ssh-action 跑 deploy-blue-green.sh（secrets: HOST/USER/KEY）
```

Node 版本统一 `actions/setup-node@v4 node-version: 22`；pnpm 用 `pnpm/action-setup`。

## 5. 上线操作手册（K 任务产出的文档 `deploy/上线手册.md`）

章节骨架（内容 K 任务写全，用户照做）：
1. VPS 选型三档与成本表（2C2G 轻量首年 ¥50-100 档起步；域名 ¥30-60/年；总预算 <¥500/年）
2. 域名购买与 DNS 解析（A 记录到 VPS IP）
3. VPS 初始化：防火墙（22/80/443）、Docker 安装、非 root 用户、SSH key
4. 仓库密钥与 secrets 配置（.env 生产版：数据库强密码/JWT_SECRET/两把 API key；GitHub secrets 三个）
5. 首次部署：clone → compose up → 迁移 → seed → caddy 证书自动签发验证
6. 日常运维：pg_dump 每日备份（cron）+ 异地存一份；日志查看（docker logs）；磁盘监控
7. 升级与回滚 runbook（跑 deploy workflow / 出事跑 rollback.sh）
8. 安全清单：gitleaks、依赖审计（pnpm audit）、限流（caddy 层 rate_limit 可选）、API key 轮换流程
