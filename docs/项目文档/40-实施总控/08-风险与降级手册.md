# 40-08 · 风险与降级手册

> 用法：出问题先查对应条目；升级条件 = 同一问题卡壳超 2 小时，或降级动作执行后仍不绿。每条降级都要在阶段总结留痕——**失败模式处理是面试亮点，不是遮丑**（归档方案调研结论 3：亮点不在堆复杂度，而在失败模式处理）。

## 1. 技术风险 → 降级动作

| # | 风险 | 触发信号 | 降级动作 | 面试叙事价值 |
|---|---|---|---|---|
| 1.1 | BullMQ job groups API 与版本不符 | P3 批次 1 分组串行不生效 | 换 Redis LIST + BRPOPLPUSH 自写派发（~50 行，00-总览/02 §4 预案），叙事不变 | 先验证官方特性，验证不过用最小自研，边界清晰 |
| 1.2 | embedding 服务不稳 / 挂 | 知识题答不出、embedMany 超时 | channel='auto' 自动降级纯词法 + embeddingHealthy 冷却期（P2 实现，P4 演练） | 降级 = 可用性设计 |
| 1.3 | hnsw.ef_search 连接池污染 | 检索结果不稳定 | 事务内 `SET LOCAL` 或 `set_config(..., true)`（10-骨架/02 §5） | 连接池 × 会话级 GUC 的真实坑 |
| 1.4 | require(esm) 运行 / 打包问题 | P1-A 首日 import 'ai' 失败 | 动态 import 封装边界层；不行则 Nest 切 ESM 编译（00-总览/02 §4 自测题 5） | ESM/CJS 互操作一手经验 |
| 1.5 | @prisma/adapter-pg 与 pg 驱动冲突 | P0 迁移或连接报错 | 锁定官方兼容的版本组合；个别查询走 $queryRaw 绕过 | driver adapter 架构理解 |
| 1.6 | @node-rs/jieba 平台二进制问题 | install / require 报错 | 确认 napi 平台包装上；CI 换 ubuntu 重试；兜底纯 JS jieba（性能数字重测并如实记录） | 预编译 vs 纯 JS 的权衡 |
| 1.7 | AI SDK 7 / Next 16 API 与文档有出入 | E/C 编译期类型报错 | 以官方 cookbook 与 changelog 为准**先改规格再改代码**，锁 minor 版本 | 版本锁定纪律 |
| 1.8 | 并行会话冲突（lockfile 损坏 / 共享文件撞车） | install 失败、合并冲突 | 按冲突处理流程回滚重放；同类冲突 ≥2 次 → 切全串行模式（总纲 §3 顺序），架构不变 | 并行工程的收益与边界 |

## 2. 质量与安全风险

| # | 风险 | 防线 |
|---|---|---|
| 2.1 | 多租户数据泄漏 | 每条 raw SQL 一个隔离测试（10-骨架/02 §5、10-骨架/04 §6）；P4 全量矩阵复跑 |
| 2.2 | 成本失控 | 阶段预算表（总纲 §5）+ 每阶段收尾对账 usage_records + 开发 demo 一律走 chat 便宜别名；全局护栏 ¥150 |
| 2.3 | 评测数字美化 | 目标值必须标注「目标」；结果表只准实测；提升不达标必须写归因（归档方案 §三） |
| 2.4 | 语料版权 | 只收公开规则页 + 来源记录完整（F 任务红线） |
| 2.5 | 简历失真 | 00-总览/04 红线 + P6 逐行自检 + P5 README 自检 |
