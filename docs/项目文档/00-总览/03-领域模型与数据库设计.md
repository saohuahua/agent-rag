# 00-03 · 领域模型与数据库设计

> 本篇是数据库的**唯一真相源**：完整 Prisma schema + 每组表的行为语义。实现会话把 schema 块原样落进 `apps/api/prisma/schema.prisma`（可微调命名风格，**不可改语义**）。
> 约定：表名 snake_case（@@map）；租户表（含 `enterpriseId` 的表）在文档中标注 `〔租户〕`；向量/词法列 `Unsupported` 类型只经 raw SQL 读写。

## 1. 核心抽象链

```
User（人类账号）
 └─ Member 〔租户〕（人在企业中的身份: 角色+部门）
     Enterprise 〔租户〕（企业=租户根）
       └─ Department（部门树, 物化路径）
       └─ Subscription（企业订阅某包, 锁定版本）
             → SubscriptionPackage → PackageVersion（不可变）→ PackageItem（模板清单）
       └─ SiliconEmployee 〔租户〕（数字员工实例 = 模板 slug+version 快照）
       └─ EmployeeGrant 〔租户〕（员工授权: 企业/部门/成员三层 scope）
       └─ ConversationSession 〔租户〕（会话: currentParticipant + epoch）
             → SessionParticipant（slot 有序阵容）→ ConversationMessage（带 employeeId+epoch）
             → ExecutionEvent（执行状态事件流）
       └─ KnowledgeDataset → KnowledgeDoc → KnowledgeChunk（向量+词法双索引）

平台级（无租户）: ModelProvider → ModelRoute（降级链） / Skill（技能注册台账）
横切: UsageRecord（算力账本, enterpriseId 可空）/ AuditLog（审计）
EmployeeTemplate 〔租户? 否，平台级〕+ TemplateSkillBinding + TemplateKbBinding（岗位模板, 版本不可变）
```

**两个最有讲头的行为，靠什么字段支撑**：
- **同会话多员工按序接管** = `SessionParticipant.slot`（顺序）+ `ConversationSession.currentParticipantId/epoch`（DB 真相）+ Redis 锁（运行时互斥）+ 消息带 `employeeId+epoch`（谁在哪个纪元写了什么，可审计）。
- **订阅版本锁定** = 模板与包**发布后不可变**（新版本=新行，`unique(slug, version)`）；`Subscription.lockedPackageVersion` 与 `SiliconEmployee.templateVersion` 是快照引用；升级是显式动作（写 AuditLog）。

/// LLM/embedding 供应商注册表 密钥只存环境变量名不存明文
model ModelProvider {

  priceInPerMTok  Decimal        @default(0) @db.Decimal(10, 4) // 元/百万输入token
  priceOutPerMTok Decimal        @default(0) @db.Decimal(10, 4)
  maxTokens      Int?
  enabled        Boolean        @default(true)
  createdAt      DateTime       @default(now())

  @@index([alias, priority])
  @@map("model_routes")
}

// ============ 岗位模板（平台级，版本不可变）============

/// 员工模板 PUBLISHED 后不可改 新行为出新版本行
model EmployeeTemplate {
  id           Int        @id @default(autoincrement())
  slug         String // rule-qa（岗位的稳定标识）
  version      Int // 1 2 3
  name         String // 规则答疑客服
  description  String
  systemPrompt String
  avatar       String?
  status       TemplateStatus
  reviewNote   String? // 审核意见/驳回原因
  createdBy    Int // Member.id（起草人）
  publishedAt  DateTime?
  createdAt    DateTime    @default(now())

  skillBindings TemplateSkillBinding[]
  kbBindings    TemplateKbBinding[]

  @@unique([slug, version])
  @@index([slug, status])
  @@map("employee_templates")
}

/// 模板↔技能绑定（含该技能的参数注入 如 kbId）
model TemplateSkillBinding {
  id         Int              @id @default(autoincrement())
  templateId Int
  template   EmployeeTemplate @relation(fields: [templateId], references: [id])
  skillKey   String // 引用 Skill.key（软引用 上架台账校验）
  configJson Json? // 参数注入 如 { "datasetId": 3 }
  order      Int              @default(0) // 工具在 prompt 里的呈现顺序

  @@index([templateId])
  @@map("template_skill_bindings")
}

/// 模板↔知识库绑定 检索内容进上下文的方式
model TemplateKbBinding {
  id         Int              @id @default(autoincrement())
  templateId Int
  template   EmployeeTemplate @relation(fields: [templateId], references: [id])
  datasetId  Int // 引用 KnowledgeDataset.id（软引用）
  kbMode     KbMode // INJECT 进system | TOOL 按需检索 | BOTH

  @@unique([templateId, datasetId])
  @@map("template_kb_bindings")
}

/// 文档分组 绑定与隔离的锚点
model KnowledgeDataset {
  id           Int           @id @default(autoincrement())
  enterpriseId Int // 〔租户〕
  name         String
  description  String?
  docs         KnowledgeDoc[]
  createdAt    DateTime      @default(now())

  @@index([enterpriseId])
  @@map("knowledge_datasets")
}

/// 上传的原始文档 解析入库状态机在这上面流转
model KnowledgeDoc {
  id           Int          @id @default(autoincrement())
  datasetId    Int
  dataset      KnowledgeDataset @relation(fields: [datasetId], references: [id])
  enterpriseId Int // 冗余存租户（chunk 检索 raw SQL 直接过滤）
  title        String
  sourceType   DocSourceType // UPLOAD | CRAWL | MANUAL
  storageKey   String // storage/ 下的相对路径
  mimeType     String
  sizeBytes    Int
  checksum     String // 内容去重（同 dataset 内重复上传拒绝）
  status       DocStatus // UPLOADED→QUEUED→PARSING→INDEXED / FAILED / OCR_NEEDED
  parseError   String?
  chunkCount   Int          @default(0)
  uploadedBy   Int // Member.id
  createdAt    DateTime     @default(now())

  chunks       KnowledgeChunk[]

  @@unique([datasetId, checksum])
  @@index([enterpriseId])
  @@map("knowledge_docs")
}

/// 检索的最小单元 向量与词法双索引列只经 raw SQL 读写
model KnowledgeChunk {
  id          Int          @id @default(autoincrement())
  docId       Int
  doc         KnowledgeDoc @relation(fields: [docId], references: [id], onDelete: Cascade)
  seq         Int // 文档内顺序
  content     String
  page        Int? // PDF 页码（可溯源）
  headingPath String? // 标题层级路径 如「三、经营讨论 > 3.2 风险」
  tokenCount  Int          @default(0)
  embedding   Unsupported("vector")? // vector(1024) raw SQL 写入/检索
  tsv         Unsupported("tsvector")? // to_tsvector('simple', 应用层分词结果) GIN 索引

  @@unique([docId, seq])
  @@map("knowledge_chunks")
}

/// 会话 currentParticipant+epoch 是并发接管的 DB 真相
model ConversationSession {
  id                   Int                  @id @default(autoincrement())
  enterpriseId         Int
  participants         SessionParticipant[]
  currentParticipantId Int? // 当前持有者 SiliconEmployee.id
  epoch                Int                  @default(0) // fencing token acquire 时原子+1
  title                String?
  status               String               @default("ACTIVE") // ACTIVE | CLOSED
  lastMessageAt        DateTime?
  createdAt            DateTime             @default(now())

  messages             ConversationMessage[]
  events               ExecutionEvent[]

  @@index([enterpriseId])
  @@map("conversation_sessions")
}

/// 会话阵容 slot 决定接管顺序
model SessionParticipant {
  id             Int                @id @default(autoincrement())
  sessionId      Int
  session        ConversationSession @relation(fields: [sessionId], references: [id], onDelete: Cascade)
  employeeId     Int
  employee       SiliconEmployee    @relation(fields: [employeeId], references: [id])
  slot           Int // 0 起始 接管按 slot 顺序

  @@unique([sessionId, employeeId])
  @@index([sessionId])
  @@map("session_participants")
}

/// 消息 parts 存 AI SDK UIMessage 的 parts 数组 text 冗余全文便于检索
model ConversationMessage {
  id         Int                @id @default(autoincrement())
  sessionId  Int
  session    ConversationSession @relation(fields: [sessionId], references: [id], onDelete: Cascade)
  role       MessageRole // USER | ASSISTANT | SYSTEM | TOOL
  employeeId Int? // 哪个数字员工写的（user 消息为 null）
  epoch      Int // 写入时持有纪元
  partsJson  Json // UIMessage parts 原样
  text       String // 冗余全文
  createdAt  DateTime           @default(now())

  @@index([sessionId])
  @@map("conversation_messages")
}

/// 执行状态事件流 type 用 String 允许扩展 标准值见 M3 规格
model ExecutionEvent {
  id          Int                @id @default(autoincrement())

  session     ConversationSession @relation(fields: [sessionId], references: [id], onDelete: Cascade)

  employeeId  Int?
  type        String // TURN_START | LOCK_ACQUIRED | TAKEOVER | SKILL_START | SKILL_PROGRESS | SKILL_END | SKILL_ERROR | DEGRADE | TURN_END
  payloadJson Json?
  createdAt   DateTime           @default(now())

  @@index([sessionId, id])
  @@map("execution_events")
}

## 3. 关键行为语义（实现时必须遵守）

| 语义 | 规则 |
|---|---|
| 模板不可变 | `PUBLISHED` 状态的 EmployeeTemplate/PackageVersion 任何字段不可 UPDATE；要改行为只能新建下一版本行 |
| 订阅锁定 | 订阅时读「当前已发布的最大版本」写入 `lockedPackageVersion`；包后续发布新版本**不影响**已有订阅 |
| 员工快照 | SiliconEmployee 的 `templateSlug+templateVersion` 在 provision 时从 PackageItem 复制；升级走显式 API（换快照+AuditLog） |
| epoch 自增 | 只在成功 acquire 会话锁之后由 worker 执行 `UPDATE conversation_sessions SET epoch=epoch+1, current_participant_id=$X WHERE id=$id RETURNING epoch` |
| 消息纪元校验 | worker 写消息的事务内先 `SELECT epoch FROM conversation_sessions WHERE id=$id FOR UPDATE`，不等于自己持有的纪元则放弃写入（锁过期被接管的迟到写） |
| 部门子树 | `path` 前后带 `/`；子树= `WHERE path LIKE $prefix || '%'`（prefix 为目标部门 path） |
| 文档去重 | 同 dataset 内 `checksum` 重复直接拒绝（409），不重复解析 |
| chunk 删除 | KnowledgeDoc 删除级联删 chunk（Cascade）；dataset 删除先校验无模板绑定 |
| 账本精度 | costCny 用 `Prisma.Decimal` 计算后写入，禁止 JS number 直写 |
