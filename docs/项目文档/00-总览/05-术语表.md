# 00-05 · 术语表

> 按首次出现顺序排列；每条=一句话定义 + 在本项目里的具体所指。

## 业务侧

| 术语 | 定义 |
|---|---|
| 硅基员工/数字员工 | 岗位化的 AI agent：有名字、职责、技能、知识库、版本，对使用它的企业而言像「雇员」。本项目中= `SiliconEmployee` 表的实例（模板快照） |
| 岗位订阅包 | 若干员工模板的打包商品（如「电商运营套装」），带不可变版本；企业订阅时锁定版本 |
| 订阅版本锁定 | 订阅后包发新版不影响已订阅企业；升级是显式动作。对应 npm 的 version pinning 语义 |
| 授权（Grant） | 数字员工可以被哪些部门/成员使用：企业级∨部门子树∨指定成员 |
| 审核上架 | 员工模板从 DRAFT→PENDING_REVIEW→PUBLISHED 的状态机，PUBLISHED 后不可变 |
| 算力统一计量 | 所有 LLM/embedding/RPA/外部 agent 调用的 token 与成本记入同一账本（usage_records） |

## 技术侧

| 术语 | 定义 |
|---|---|
| RAG | 检索增强生成：先从知识库检索相关片段，再让 LLM 基于片段回答 |
| 双路召回 | 向量检索（语义）+ 词法检索（关键词）并行各自取 top-N |
| RRF | Reciprocal Rank Fusion：只用各路**排名**的融合公式 `Σ 1/(k+rank)`，k=60；不需要分数可比 |
| HNSW | 分层可导航小世界图，pgvector 的近似最近邻索引；参数 m=16、ef_construction=200、ef_search 运行期可调 |
| `<=>` | pgvector 余弦距离算符（越小越近）；索引与查询必须同用 cosine ops |
| tsvector / tsquery / GIN | Postgres 全文检索三件套：分词后的文档向量、查询表达式、倒排索引 |
| `to_tsvector('simple', x)` | 不做词干/停用词的「simple」配置——中文靠应用层 jieba 分词后空格拼接喂给它 |
| ts_rank | PG 全文检索的相关性排名（TF 类），**不是 BM25**——RRF 只用排名所以无害，文档如实写 |
| bge-m3 | BAAI 的多语言 embedding 模型，1024 维、8k token 上下文；本项目经 SiliconFlow API 只用 dense 输出 |
| BullMQ | 基于 Redis 的任务队列；job groups 特性让同一 group（=同一会话）的 job 串行执行 |
| WorkerHost | @nestjs/bullmq 的处理器基类，按 job.name 分发 |
| 会话锁 | `SET key token NX PX 30000` + Lua 续期/释放 + watchdog；防同会话并发写坏上下文 |
| epoch / fencing token | 单调递增整数，锁 acquire 时 DB 原子 +1；写入校验纪元，拦下锁过期后旧持有者的迟到写 |
| ALS | AsyncLocalStorage：Node 的请求级上下文（类比 React Context 的服务器版），EnterpriseContextService 的载体 |
| 物化路径 | 树结构存「根到节点」的 id 链字符串（`/1/3/7/`），子树查询一个 LIKE 搞定 |
| OpenAI-Compatible | 与 OpenAI API 请求/响应形状一致的协议（`/v1/chat/completions`、`/v1/embeddings`）；DeepSeek/SiliconFlow 都遵循 |
| UI Message Stream | AI SDK v5+ 的前后端流协议（SSE 载荷 JSON chunk：text-delta / data-* / source 等） |
| streamText / useChat | AI SDK 后端生成入口 / 前端消费 hook |
| sub2api | 开源「订阅转 API」网关（把 Claude Pro/ChatGPT Plus 等订阅账号转成 API 分发，43k star）；有 ToS 风险，本项目不部署，只做面试话术对照 |
| 降级链 | 同一 alias 的多条 ModelRoute 按 priority 排序，上游 5xx/超时自动换下一跳 |
| 蓝绿部署 | 两套相同环境（蓝/绿），流量在路由层一键切换，旧环境即回滚安全网 |
| expand-contract | 数据库变更纪律：先加可空新列（expand）→ 双版本兼容运行 → 再删旧列（contract），保证蓝绿两版共存时 schema 兼容 |
