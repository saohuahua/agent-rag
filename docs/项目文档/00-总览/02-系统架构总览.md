## 2. 一次「售后工单处理」的完整数据流（走读主线）

1. 用户在 web 会话页发消息 → `useChat` 经 `DefaultChatTransport` POST 到 `api:3002/api/sessions/:id/turns`；
2. API 把 turn 投进 BullMQ `agent-turn` 队列（**job group = sessionId**，保证同一会话同一时刻只跑一个 turn），立即返回 SSE 流句柄；
3. worker 取 job：**acquire Redis 会话锁**（SET NX PX + watchdog 续期）→ **DB epoch 原子自增**（fencing token）；
4. 加载会话上下文（消息史+当前员工模板）→ 模板配置的技能包装成 tools → `streamText`（经 **M1 网关**路由到 DeepSeek/SiliconFlow，onFinish 计量入账）；
5. LLM 决定调 `kb_search` 工具（M2 双路召回+RRF）→ 决定调 `operate_ticket`（HTTP_RPA 打 mock 工单系统）→ 执行状态以 ExecutionEvent 落库并推 SSE；
6. LLM 输出流式增量 → pipeUIMessageStreamToResponse → 前端打字机渲染；
7. 消息持久化（带 employeeId+epoch）→ **释放锁** → TURN_END；
8. 全程每一次模型调用、每一次技能执行都写 `usage_records`（token/成本/延迟）。

## 3. 技术基线（版本一次锁定，全部经 2026-09-29 官方源核实）

| 层 | 选型 | 版本 | 一句话理由 |
|---|---|---|---|
| 运行时 | Node.js | ≥22.12（本机 22.23.2） | AI SDK 7 要求 ≥22 且 ESM-only；Nest 12 要求 ≥20.19/22.12；`require(esm)` 需 ≥22.12 |
| 包管理 | pnpm workspaces | 11.x（本机） | monorepo 基座；暂不引 Turborepo（两 app 两进程，`pnpm --parallel` 够用，心智负担最小） |
| 后端 | NestJS | ^12 | 12.0.0（2026-08-27）当前稳定大版本；Standard Schema 可直挂 zod |
| 前端 | Next.js + React | ^16 + 19 | App Router + AI SDK 官方一等支持 |
| AI 编排 | Vercel AI SDK | ^7.0 | 2026-06-25 GA；官方 NestJS cookbook 配方成熟 |
| ORM | Prisma | ^7.10 + @prisma/adapter-pg | 7.x 是当前稳定线（8 仍 RC 勿用）；driver adapter 架构 |
| 向量 | pgvector（Postgres 17 镜像） | 0.8.x | HNSW 索引 + `<=>` 余弦距离 |
| 队列/锁 | Redis + BullMQ | 7 / ^6 + @nestjs/bullmq ^12 | 官方 Nest 集成；job groups 实现按会话串行 |
| 校验 | zod | ^4.6 | AI SDK peer 与 Nest Standard Schema 双满足 |
| 解析 | pdf-parse 2.x / mammoth | — | PDF 文本+表格；docx |
| 分词 | @node-rs/jieba | 2.x | Rust napi 预编译（win32-x64 免 node-gyp） |

## 4. 关键选型的 trade-off（面试深挖答案库）

| 选了什么 | 没选什么 | 为什么（一句话） |
|---|---|---|
| 自写薄网关（~几百行） | LiteLLM / one-api / sub2api | 计量计费/降级/预算全掌控+教学可讲；sub2api 是「订阅转 API」有 ToS 风险，我们用官方 API 聚合，保留它真正有价值的工程（统一计量） |
| pgvector + tsvector 单库双索引 | Qdrant/Milvus + ES | 一个 Postgres 同时管向量/词法/业务数据，运维与事务一致；规模到千万级 chunk 才值得拆专用引擎 |
| 应用层 RRF | SQL 层融合 | 降级语义天然成立（少一路就单路）；计算量极小；SQL 混合参数复杂度不值 |
| jieba 应用层分词 + simple 配置 | zhparser / pgroonga | 免自定义 PG 镜像、Windows 零编译；ts_rank 非 BM25 但 RRF 只用排名（文档如实写） |
| Redis SET NX + Lua + DB epoch | redlock 库 | redlock 休眠 4 年+Kleppmann 批评（无 fencing、依赖时钟假设）；单 Redis 效率型锁 + DB epoch 兜底正确性是教科书方案 |
| BullMQ job groups | 自写 Redis LIST 派发 | 官方特性免维护；若 API 不符降级为 LIST+BRPOPLPUSH（~50 行，叙事不变） |
| ALS + Prisma 扩展行级过滤 | Postgres RLS | driver adapter 连接池下 `SET app.*` 会话管理复杂、ORM/raw 双轨更易漏；用测试矩阵兜住（每条 raw SQL 一个隔离测试） |
| 模板/包不可变版本行 | 单表 version 字段 | 审计/回滚/diff 全要靠不可变快照——这正是「订阅版本锁定」的语义根基 |

## 5. 横切约定（全项目统一）

- **协议**：对外一切模型调用走 OpenAI-Compatible 形状；前端对话走 AI SDK UI Message Stream（SSE）；
- **密钥**：只存 env 变量名于 DB（`ModelProvider.apiKeyEnv`），明文只在 `.env`；
- **计量**：所有 LLM/embedding/RPA/外部 agent 调用必须落 `usage_records`，成本 `Decimal(10,6)` 精算；
- **租户**：所有业务表带 `enterpriseId`，经 EnterpriseContextService 过滤（见 M4 规格）；
- **可观测**：ExecutionEvent 是运行行为的唯一持久化事件流（回放/时间线/审计共用）。
