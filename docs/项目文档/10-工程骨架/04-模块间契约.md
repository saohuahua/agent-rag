# 10-04 · 模块间契约（并行执行的基石）

> **跨模块只允许通过本篇定义的接口交互**。任务 0 把所有契约落成「接口 + 抛 NOT_IMPLEMENTED 的桩类」；各任务把桩替换成真实现时**必须保持导出名与方法签名不变**。这样 A-H 任务可以完全并行：编译期互认（导入桩类），运行期在集成任务 J 才真正连通。

## 0. 依赖方向图（单向 禁环）

```
tenant(上下文) ──被依赖──> rag / runtime / skills
gateway(网关)  ──被依赖──> rag / runtime / skills
skills(执行器) ──被依赖──> runtime
rag(检索)      ──被依赖──> runtime
shared(类型)   ──被依赖──> 所有
事件回传用「函数参数注入」（EventSink）不走模块 import（见 §5）
```

## 2. GatewayService 契约（A 实现）

```typescript
import type { ModelMessage } from 'ai'

/** 一次模型调用的用量事实（计量入账后返回给调用方） */
export interface UsageInfo {
  inputTokens: number
  outputTokens: number
  providerName: string // 实际命中的 provider 如 deepseek
  model: string        // 实际上游模型名
  routeAlias: string   // 请求时的逻辑别名
}

/** 流式对话结果 文本增量流 + 完成时的用量 Promise */
export interface GatewayStream {
  textStream: AsyncIterable<string>
  usage: Promise<UsageInfo>
}

@Global()
export class GatewayService {
  /** 非流式对话（粗活场景 判分/改写等） */
  async chat(opts: {
    messages: ModelMessage[]
    alias: string            // 'chat' | 'strong-chat' | 自定义
    ctx?: TenantCtx          // 有租户上下文则计量归属该企业
    temperature?: number
  }): Promise<{ text: string; usage: UsageInfo }>

  /** 流式对话（Runtime 的主对话链路） */
  chatStream(opts: {
    messages: ModelMessage[]
    alias: string
    ctx?: TenantCtx
    temperature?: number
  }): Promise<GatewayStream>

  /** 批量向量化（RAG 入库与查询共用） B 任务消费 */
  async embedMany(texts: string[], ctx?: TenantCtx): Promise<number[][]>

  /** embedding 通道健康状态（连续失败进入冷却期为 false） B 的降级信号 */
  embeddingHealthy(): boolean
}
```

## 3. UsageMeter 契约（A 实现 C/H 调用）

```typescript
/** 算力账本统一入口 所有耗资源调用（LLM/RPA/外部agent）必须记账 */
export interface UsageMeter {
  record(entry: {
    kind: 'LLM' | 'EMBEDDING' | 'RPA' | 'EXTERNAL_AGENT'
    routeAlias: string
    providerName: string
    model: string
    inputTokens?: number
    outputTokens?: number
    costCny: number      // Decimal 序列化后的数字（RPA 类无 token 时只记成本与耗时）
    latencyMs: number
    success: boolean
    errorCode?: string
    ctx?: TenantCtx      // 计量归属
    sessionId?: number
  }): Promise<void>
}
```

LLM/embedding 的记账在 GatewayService 内部完成（onFinish 钩子）——C/H 只对 RPA 与外部 agent 调用显式记账。

## 4. RetrievalService 契约（B 实现）

```typescript
/** 检索命中项 两路排名与融合分都返回 供评测与前端可视化 */
export interface RetrievalHit {
  chunkId: number
  docId: number
  content: string
  headingPath?: string | null
  page?: number | null
  vectorRank?: number   // 向量路名次（该路未参与则为 undefined）
  lexicalRank?: number  // 词法路名次
  rrfScore: number      // 融合得分（单路时即该路折算分）
}

export class RetrievalService {
  /**
   * 双路混合检索 向量路与词法路并行 RRF 融合
   * channel='auto'：embedding 不健康或向量路失败时自动降级纯词法
   */
  hybridSearch(opts: {
    enterpriseId: number
    query: string
    topK?: number           // 默认 8
    channel?: 'auto' | 'vector' | 'lexical'  // 评测用后两者做消融
  }): Promise<RetrievalHit[]>
}
```

## 5. SkillExecutor 契约（H 实现）

```typescript
import type { ZodType } from 'zod'

/** 技能定义（上架台账的代码侧真相） */
export interface SkillDef {
  key: string                       // kb_search | operate_ticket | ...
  type: 'BUILTIN_FUNCTION' | 'HTTP_RPA' | 'EXTERNAL_AGENT'
  description: string               // 给 LLM 看的用途描述 直接进 tool description
  inputSchema: ZodType              // zod schema 即工具入参协议
  riskLevel: 1 | 2 | 3
}

/**
 * 事件回传以函数参数注入 避免 skills→runtime 的反向依赖
 * emit 由 runtime 构建工具时注入 内部写 execution_events 并推 SSE
 */
export type EventSink = (type: string, payload?: unknown) => Promise<void>

/** 技能执行上下文 */
export interface SkillCtx {
  sessionId: number
  employeeId: number
  templateSlug: string
  configJson: unknown | null   // 模板绑定该技能时的参数注入 如 { datasetId: 3 }
  ctx?: TenantCtx
  emit: EventSink              // 发 SKILL_PROGRESS 等事件
}

/** 执行结果 output 必须可 JSON 序列化 summary 是给 LLM 的一句话摘要 */
export interface SkillResult { output: unknown; summary: string }

export abstract class SkillExecutorRegistry {
  /** 全部可用技能的定义（runtime 据此构建 tools） */
  listDefs(): SkillDef[]
  /** 按 key 执行 入参先过 inputSchema 校验 非法输入抛 SkillInputError */
  async execute(opts: { skillKey: string; input: unknown; skillCtx: SkillCtx }): Promise<SkillResult>
}
```

## 6. EnterpriseContextService 契约（D 实现）

```typescript
/** 请求级租户上下文（ALS 载体） */
export interface TenantCtx {
  enterpriseId: number
  memberId: number
  role: 'OWNER' | 'ADMIN' | 'MEMBER'
}

@Global()
export class EnterpriseContextService {
  /** 在指定上下文中执行 fn（ALS enter/exit）worker 与脚本用 */
  run<T>(ctx: TenantCtx, fn: () => Promise<T>): Promise<T>
  /** 当前上下文（无则 null）请求处理链路用 */
  current(): TenantCtx | null
  /** 必须有上下文否则抛 TenantIsolationError（拿到即说明 Guard 没接对） */
  require(): TenantCtx
}
```

Prisma 租户过滤扩展由 D 提供（`src/tenant/prisma-tenant.extension.ts`），任务 0 在 PrismaService 上**预留挂载点注释**，D 完成后启用——这是唯一一处 D 需要触碰共享文件的例外，**由 D 任务产出补丁说明，用户手动应用**（见 prompts/README 的冲突处理）。
