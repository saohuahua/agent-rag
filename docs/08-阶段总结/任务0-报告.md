## 2. 与文档计划的偏差（已回写文档）

1. **API 端口 3001 → 3002**：本机 3001 被用户另一项目（agentDesk/pi-web-vue Nuxt）占用；MOCK_RPA_PORT 相应 3002→3003。所有文档已同步。
2. **packages/shared 改为构建包**（tsc 出 dist+声明文件），不再是「ts 源码直引」——原方案会把 tsconfig rootDir 推到仓库根导致 dist 路径错位（实测踩坑）。改 shared 源码后需重跑 build。
3. **@nestjs/config 移除**：其 peer 尚不支持 Nest 12；它在本项目只干 .env 加载一件事，改为 env.service.ts 顶层的 20 行自写加载（真实 env 优先不覆盖）。
4. **EnvService 升级为 @Global 的 EnvModule**：BullMQ forRootAsync 的动态模块注入看不到普通 provider（DI 上下文隔离，实测）。
5. schema 修正：canonical 文档原有 7 处不成立的 relation 字段（packageItems/templates/messages/events/datasets/sessions/subscriptions 缺反向），Prisma 校验抓出后已修齐并回写文档。
6. infra 脚本三件：infra-up/infra-down/pg-server（PGlite 长驻服务由 infra-up 派生，pid 文件树杀）。

## 3. 踩坑实录（文档已记录，面试可讲）

| # | 坑 | 解法 |
|---|---|---|
| 1 | pglite-socket maxConnections 默认 1，第二个连接被踢 | 显式设 32（≥ pg 池大小） |
| 2 | Prisma DDL 的 vector 列无维度，HNSW 建索引报 column does not have dimensions | 手写区 ALTER TYPE vector(1024) |
| 3 | npm latest 的 prisma 是 8.0-RC（CLI 命令全变） | 显式 pin ^7.10 |
| 4 | PGlite 单库无 shadow database → migrate dev 不可用 | 自研 60 行 runner + 生产 migrate deploy 双轨 |
| 5 | tsconfig include prisma/** + paths 指向仓库外 → rootDir 推到项目根、dist 错位 | include 收敛为 src/** + prisma/tests 单独 tsconfig + shared 构建化 |
| 6 | JSDoc 注释里 `migrations/*/migration.sql` 的 `*/` 提前终止块注释（语法错误） | glob 写法改文字描述 |
| 7 | 3001 端口被占用 | 换 3002 |
| 8 | pnpm 11 默认拦截 prisma/esbuild 构建脚本 | workspace yaml allowBuilds 显式批准 |

## 5. 给用户的讲解提纲（学习主线：一次 LLM 调用之前的世界）

1. **monorepo 为什么**：api（NestJS 后端）/ web（Next 前端）/ shared（共享类型）/ mock-rpa（模拟外部系统）+ 根统一脚本——前后端共享一个类型包，改契约不会两端不同步。
2. **本地「数据中心」**：`pnpm db:up` 起两个服务——PGlite（把 Postgres 编译成 WASM 跑在 Node 进程里，再用 socket 服务翻译成标准协议，所以 Prisma 以为自己在连真 Postgres）+ Windows 原生 Redis。
3. **目录骨架与契约桩**：五个模块目录已建好、接口已定义、桩会抛 NOT_IMPLEMENTED——后续任务各自填自己的目录，互不碰文件（并行执行的基础）。
4. 建议阅读顺序：docs/10-骨架/01 → 02 → 04，对照 `apps/api/src/` 走读 main.ts → app.module.ts → env.service.ts。
