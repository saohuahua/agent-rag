# 并行执行 Prompt 包使用说明

> 用法：每个文件是一段完整 prompt，**复制全文**粘到一个新会话（Claude Code / Codex 均可）即可开工。本说明讲清楚哪些能同时开、哪些必须排队。
> **无需 Docker**：本地基础设施 = PGlite（内嵌 Postgres）+ Windows 原生 Redis，已在用户机器上验证通过（2026-09-29）。`pnpm db:up` 一键起。

## 并行模型（30 秒版）

```
第一步（单独跑，别的都别开）:  00-任务0-基座.md
第二步（随便多开，互不阻塞）:  A-网关  B-RAG  C-Runtime  D-多租户  E-前端
                               F-语料采集  G-mock工单  H-技能执行器
第三步（全部完成后再开）:      J-集成评测种子.md   （可与 K 并行）
                              K-交付部署.md
```

**为什么能无阻塞并行**：任务 0 已把全部共享资源一次建齐（全量数据库 schema、依赖、目录骨架、跨模块契约桩）；每个任务**独占一个目录**、只读别人；缺了谁的实现，调用契约桩会抛清晰的 `NOT_IMPLEMENTED`，编译不受影响。

## 开多少个并行合适

- 建议 3-5 个（太多你也看不过来）；推荐首批 **A + B + F + G**（F/G 是纯内容任务最快出活，A 是其他任务的依赖底座，B 最独立）。
- 每个会话用独立的终端/窗口；它们写不同目录不会互相覆盖文件。

## 每个会话的硬纪律（prompt 里已写，这里给用户做 review 用）

1. 只写自己目录（目录所有权表：docs/40-实施总控/01 §2）；
2. 不 `pnpm add`（依赖任务 0 已装齐；缺了会写进报告申请）；
3. 不 commit/push——完成后写报告到 `docs/08-阶段总结/`，**由你统一 review 后提交**；
4. 遵守 docs/10-工程骨架/03-代码规范.md（自查清单在 §10）。

## 你（用户）在每个节点要做的事

| 节点 | 你做什么 |
|---|---|
| 任务 0 完成 | 对照 docs/10-骨架/01 §6 验收清单逐条过；把 API key 填进 `.env` |
| 每个任务报告出现 | review diff（对照所有权表看有没有越界）+ 让主会话给你讲解（学习）+ 统一 commit |
| 并行任务全部完成 | 跑 J（和可并行的 K）；J 的报告是全项目「真实数字」的汇总点 |
| J/K 完成 | 按保真度表（00-总览/04）自检；进入面试资产阶段（/project-guide → /great-resume → /interview） |

## 出问题怎么办

- 两个会话都改了同一文件（不应该发生）：以后跑的为准手工合并，并在报告里记违纪；
- 某任务卡死：把它停掉，看它报告里的「契约变更提案」和阻塞点，回主会话（本对话）讨论；
- 契约要改：只允许在主会话/串行会话里改 `docs/10-骨架/04` 和对应桩文件，改完通知所有进行中的会话重新读文档。
