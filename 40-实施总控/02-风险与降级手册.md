## 2. 叙事风险（面试质疑应对）

| # | 质疑 | 应对 |
|---|---|---|
| N1 | 「复刻别人简历项目=抄袭包装」 | README 显式复刻声明+差异表（身份/数字/接入方式全不同）；教学文档+真实数字+开源可复现本身就是差异化证据 |
| N2 | 「数字员工=套壳」 | 讲平台工程价值：岗位化封装/审核上架/版本锁定/授权/计量是「平台」该做的事；LLM 只是产能单元；demo 里每个岗位有可跑的结构化产出 |
| N3 | 「评测集才 40 题」 | 诚实标注规模与局限；方法论（消融/分题型/可复现脚本）比规模可信；引用「评测必问」的调研结论自证方法论完备 |
| N4 | 「为什么不用 LangGraph/多 agent 框架」 | 「Illusion of Agentic Complexity」类研究结论+我们的「多员工」是业务岗位轮转非技术 agent 图；复杂度收敛是设计而非不会 |
| N5 | 「sub2api 为什么不用」 | 讲清它是什么（订阅转 API 分发）、原项目图什么（额度拼车+计量）、我们的合法替代（官方 API 聚合+同款计量工程）——知道且不用=加分 |
| N6 | 「并发才两个请求的锁是不是过度设计」 | 锁+fencing 是「正确性不随规模打折」的语义要求；演示脚本证明行为可预期；反问「没有锁时两个 turn 谁先谁后」 |
| N7 | 「没上生产」 | 本地蓝绿演示零停机证据+CI 全绿+上线手册完整（「已具备上线条件，按手册 30 分钟可完成」）；如实说「个人项目无真实流量」 |

## 3. 烂尾防线

- 每任务有独立验收（可跑版本）+总结报告，完成即封箱；
- 最低保底线=任务 0+A+B+C（网关/RAG/Runtime=简历三大件）；D/E/F/G/H/J/K 逐级可裁（裁掉的部分简历不写对应词即可——保真度表反查）；
- 用户侧节奏：每完成一批任务做一次讲解对话（00-总览/06 的固定动作），保持理解跟进度走。
